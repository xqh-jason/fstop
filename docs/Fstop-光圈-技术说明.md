# Fstop · 技术说明：在浏览器里做照片语义检索

> 面向读者：想弄清「不装东西、不搬照片、不上传」到底怎么做到的人，以及想评估这套做法能不能
> 用在自己场景里的人。所有数字都来自本仓库 `bench/` 下的脚本，可复跑；引用时请连**测量环境**
> 一起引（原因见 §5 第一条教训）。

## 1. 一句话

把「照片语义检索」这条链路整体搬进浏览器标签页：**句柄代替拷贝、WebGPU 跑 CLIP 家族模型、
索引落在浏览器自己的存储里**。没有服务端、没有账号、没有 CUDA、没有 Docker，
也不需要把照片搬进某个目录。

## 2. 链路与取舍

    list()/read()/stat()  →  decode  →  embed（WebGPU）  →  thumb  →  向量矩阵(OPFS)  →  SQLite(OPFS)
        PhotoSource          摆正+降采样      单塔 CLIP        320px q0.8      扁平 Float32 追加      队列+照片+人脸

每一步都有一处「为什么不那样做」：

| 决定 | 替代方案 | 为什么不用它 |
|---|---|---|
| **文件句柄**（File System Access） | 上传到服务器 / 复制进应用目录 | 承诺是「照片不复制」。句柄让 `read()` 按需取原始字节，索引结束后连缩略图都在本机 |
| **扁平 Float32 矩阵**（自实现顺序追加） | IndexedDB 一条一条存向量 / HNSW 索引 | 1 万 × 512 × 4 B ≈ 20 MB，整块读进内存后余弦排序是**毫秒级**（实测 7.3 ms）。HNSW 在万张量级是过度设计，还要维护图结构 |
| **自实现的 SQLite（`opfs-sahpool`）** | 直接用 OPFS 存 JSON / 用 IndexedDB | 需要事务、增量扫描、任务队列与崩溃恢复。第二实例会硬失败，所以配了 Web Locks 选主：第二标签页**退化成只读**而不是报错 |
| **重导出的 192² 单塔** | 直接用原版双塔 | 单张成本 97% 在视觉塔，但「白算文本塔」的旧结论是**跨模型混淆**（见 §5） |
| **索引期间可检索** | 索引完再开放检索 | 每次查询重读矩阵（换几毫秒，换来「边索引边用」）。矩阵是追加式的，读到一半的库也是自洽的 |

## 3. M0 五项实测（决定后面所有数字）

环境：macOS / **系统 Chrome 153.0.0.0（headless）** / WebGPU 可用 / 真实语料 783 张 Wikimedia CC0 原图（1.71 GB）。

| # | 实测项 | 结果 | 判定 |
|---|---|---|---|
| 1 | 首启体积与 dtype | 默认 q4f16 档 125.8 MB；重导出单塔降到 **47.5 MB** | 通过（链路速率留档：本机经代理 ~0.45 MB/s，用户直连 2.6 MB/s） |
| 2 | 单张向量化（冷/热） | 热 **154 ms**（真实语料 783 张）；q4f16 比 fp16 慢 13–16% 但只有 1/3.5 体积 | 通过（≤150 ms 一档，取保守值继续） |
| 3 | HEIC 能否解开 | **不能**。Chromium 不支持 HEIF/HEVC 解码 | 定稿：明确排除，不引 libheif wasm（用户无 iPhone/RAW 真机样张，覆盖无法补齐） |
| 4 | 端到端 photos/s | 默认双塔 **13.6 张/秒 → 1 万张 12.3 分钟**；重导出单塔 **18.56 → 9.0 分钟** | 过验收线（≤20 分钟），单塔过冲刺线（≤10 分钟） |
| 5 | `opfs-sahpool` 两标签页 | 第二实例硬失败 → 用 Web Locks 选主优雅退化 | 通过（`bench/e2e-tabs.mjs` 三断言钉住） |

三条被这次实测推翻/确认的假设，值得单独说：

- **ORT 的 WebGPU EP 不剪枝输出**：只取 `image_embeds` 与跑全量耗时相同（59 ms）→
  「按需剪枝省算力」这条路出局，方案改为「换更小的输入图」。
- **「文本塔白算 59%」是错的**：那是跨模型比较（两个模型视觉塔 token 数差 4 倍）。同一模型内单变量
  实测，占位文本只有两个 token → 约 **0.5 ms**。成本归因必须在同一模型内做。
- **浏览器构建版本对数字的影响大于模型选择**：同机同语料，环境 A 4.38 张/秒 vs 环境 B 9.96 张/秒
  （decode 175→43 ms，embed 320→201 ms）。**基准结果不连浏览器版本一起记录就没有意义。**

## 5. 翻过的车（按「会重犯」排序）

1. **浏览器版本 > 模型选择**（见上）。
2. **GPU 单会话约束对每条新推理路径都要重新执行一次**：照片嵌入踩过（并发提交导致标签页空转卡死），
   人脸链又踩了一次。修复方式是把**推理**串起来、解码/读盘仍并发（吃满 CPU 填 GPU 空档）。
3. **调优值是有主人的**：人脸链直接复用了照片嵌入的解码尺寸（512 px 是给 CLIP 调优的），
   结果小脸检不到。抽成各自的常量，别搭便车。
4. **夹具错了先修夹具**：人脸端到端一度报「把两个人合成一组」，真凶是语料里混进了合影与文字图，
   「按照片文件名标注人物」这个前提根本不成立。测试失败时先问 ground truth 站不站得住。
5. **「数字看起来合理」不等于「数字是对的」**：一次写入 bug 让每张照片只剩最后一张脸，
   端到端显示「9 张脸 / 9 张照片，全是单脸」，看着毫无破绽。
6. **规范化先除后套**：`(v-127.5)/127.5` 在「先除以 255 再套 mean/std」的实现里要写成 `mean/std = 0.5`；
   写成 127.5 会让输入塌成常数，模型输出全是噪声（max score 0.014）。**别猜，扫出来**：
   `bench/face-probe.mjs` 的 `PROBE_MODE=sweep` 一次跑 7 种预处理变体。
7. **承诺要看真实请求，不是自述**：离线面板用 `PerformanceObserver('resource')` 记浏览器**真发出的**
   请求。同时注意**部署后页面自己的 origin 不是 localhost**——只看 host 白名单会把 app 自己的资源
   判成违规，一个会误报的面板等于没有面板。
8. **绝对像素不要跨尺度复用**：人脸封面曾按**原图像素**算放大倍数、却作用在 **320 px 缩略图**上，
   倍数大了约 12.5 倍，格子只剩一块皮肤（用户看到的是「各色纯色」）。CSS 里只用无单位比例 +
   `calc` 乘容器尺寸，算式与任何一层的分辨率都无关。
9. **几何对齐优先对齐中心，不要对齐左上角**：左上角要求同时知道「脸的宽高各占格子多少」，
   漏掉照片高宽比因子就偏出约 30%（用户看到的是「照片一角」）；对齐中心只要一个点。
10. **数据断言全绿 ≠ 画面对**：M2 的分组/命名/合并/拆分/零外发断言全绿时，用户一眼看到的仍是白图。
    UI 交付必须配**像素级断言**（元素存在 + 尺寸符合算式 + 可见窗口对准目标中心 + 裁切区像素有内容）。
    另外：断言自己也会写错——报红先怀疑断言，再动产品代码。

## 6. 诚实的限制

- **标签页关闭即停**：浏览器路线的固有短板，索引不会在后台继续。要常驻后台只能上原生壳（M4，Tauri 2）。
- **HEIC / RAW 不支持**（Chromium 解不开，明确排除而不是假装支持）。
- **平台**：桌面 Chromium（目录选择器 + WebGPU）。Firefox / Safari 缺目录选择器，移动端不在范围。
- **人脸语料只有 7 张、2 个人**：能证明「不混人 + 同人成组」，给不出召回率/准确率的量化结论。
- **模型许可**：人脸识别用的 `antelopev2`（insightface 系）是**非商用**条款，启用即约束整个项目；
  权重不随仓库分发（见 `NOTICE`）。
- 索引阶段的预处理仍走 512² 再缩到 192²，可以直接出 192² 省一次画布缩放（已列为待办，未做）。

## 7. 复现

```bash
pnpm install
pnpm dev                      # 打开打印的 localhost 地址，点「先试用内置样例」即可跑通全链路（39 张 CC0 样例）
pnpm verify                   # 单测 + lint + typecheck + 静态零外发断言
pnpm build && node bench/e2e-samples.mjs   # 构建产物静态托管端到端（样例索引 + 检索 + 零外发）
node bench/e2e-app.mjs        # 产品路径端到端（真实语料：扫描 → 增量 → 入库 → 处理 → 检索）
pnpm bench                    # 吞吐/质量基准（需要先备好真实语料，见 bench/corpus-manifest.json）

# 发布形态（给别人用的产物）
pnpm build && pnpm release:package                          # 打出剥离了派生权重的发布物 + 校验和
E2E_DIST=~/code/fstop-release/fstop-0.3.0-dist \
  node bench/e2e-samples.mjs                                # 验证发布物本身（走原版双塔回退路径）
```
